# Migrate from ERUI API 1.1 to API 1.2

API 1.2 is an additive source update introducing Numeric Slider and Custom
Slider. Existing controls and API 1.1 call shapes remain unchanged.

Migration is optional. A client already compiled against API 1.1 continues to
request the frozen API 1.1 table and works with later compatible 1.x hosts. A
client only needs the API 1.2 SDK when it wants an API 1.2 feature.

## What changes when source adopts the new SDK

The API selected by the header-only wrapper changes:

```text
API 1.1 ERNativeUI.hpp -> erui::connect() requests API 1.1
API 1.2 ERNativeUI.hpp -> erui::connect() requests API 1.2
```

No call-site argument is added to `connect()`. Rebuilding with the API 1.2
header therefore raises the client's minimum host requirement even when its
menu source otherwise remains unchanged. Ship the API 1.2-compatible host to
players who use that rebuilt client.

## Replace a byte Slider only when useful

An existing byte Slider remains correct and does not need migration:

```cpp
erui::SliderOptions volume{};
volume.minimum = 0;
volume.maximum = 100;
volume.step = 5;
volume.initial_value = 50;

page.add_slider(L"Volume", L"Adjust the volume.", volume);
```

Use Numeric Slider when the public value is signed or decimal:

```cpp
erui::NumericSliderOptions distance{};
distance.minimum = 0.1;
distance.maximum = 2.0;
distance.step = 0.1;
distance.initial_value = 0.6;
distance.decimal_places = 1;
distance.prefix = L"x";

page.add_slider(
    L"Camera Distance",
    L"Adjust the camera distance.",
    distance);
```

The option type chooses the overload. The byte Slider's callback and
`Registration::get_value`/`set_value` remain unchanged. Numeric Slider instead
uses `NumericSliderChange` and the typed numeric getter/setter.

Use Custom Slider when position labels do not form an arithmetic sequence:

```cpp
static constexpr std::array<std::wstring_view, 3> labels{
    L"Calm", L"Wild", L"Unthinkable"};

erui::CustomSliderOptions style{};
style.value_count = static_cast<std::uint32_t>(labels.size());
style.initial_index = 0;
style.format_value =
    [](std::uint32_t index, std::uint32_t) -> std::wstring {
        return index < labels.size()
            ? std::wstring(labels[index])
            : std::wstring{};
    };

page.add_custom_slider(L"Style", L"Choose a style.", style);
```

The C++ formatter executes during registration only. The host copies every
returned label and later reports a zero-based index.

## Capability checks

For an optional feature, check the exact capability where the menu is built:

```cpp
if (menu.supports(erui::Capability::numeric_slider)) {
    // Add Numeric Slider rows.
}

if (menu.supports(erui::Capability::custom_slider)) {
    // Add Custom Slider rows.
}
```

The API 1.2 wrapper validates its required table during connection. Local
capability checks still document the dependency and allow one optional menu
section to be omitted cleanly.

## Strict-C clients

A strict-C client that adopts API 1.2 must:

1. set `ERUI_Api.size` to `ERUI_API_V1_2_SIZE`;
2. request `ERUI_API_VERSION_1_2`;
3. check `ERUI_CAP_NUMERIC_SLIDER` or `ERUI_CAP_CUSTOM_SLIDER`; and
4. use only the new descriptor and typed getter/setter block after negotiation
   succeeds.

Do not enlarge an API 1.1 table in place while continuing to request API 1.1.
The version and declared size describe one frozen contract together.

## Validation checklist

- Build against the intended API 1.2 SDK package.
- Test connection failure with an API 1.1-only host; the mod's gameplay
  functionality should remain usable without its optional menu.
- Test each declared initial value and both ends of every slider.
- Close and reopen the page to confirm the displayed value remains correct.
- Test programmatic getters/setters and confirm they do not invoke the
  player-change callback.
- Retest coexistence with other native-menu mods used by the project.
