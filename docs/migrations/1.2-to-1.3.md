# Migrate from ERUI API 1.2 to API 1.3

API 1.3 is an additive source update introducing client-owned top-level tabs
in Elden Ring's System screen. Existing pages, controls, callbacks and API 1.2
call shapes remain unchanged.

Migration is optional. A client already compiled against API 1.2 continues to
request the frozen API 1.2 table and remains compatible with later hosts in
the same release-major line. Adopt API 1.3 only when the mod needs its new
surface or intentionally raises its minimum host requirement.

Package-release versions and ERUI API versions are independent. Build against
an SDK that explicitly exposes API 1.3 rather than inferring support from the
package filename alone.

## What changes when source adopts the new SDK

The API selected by the header-only wrapper changes:

```text
API 1.2 ERNativeUI.hpp -> erui::connect() requests API 1.2
API 1.3 ERNativeUI.hpp -> erui::connect() requests API 1.3
```

No argument is added to `connect()`. Merely rebuilding existing source with
the API 1.3 headers therefore requires a host exposing the complete API 1.3
table. The wrapper intentionally does not negotiate down to API 1.2.

## Add a top-level tab only when it fits the mod

An API 1.2 client commonly places settings on a built-in page or in a submenu:

```cpp
erui::Page page = menu.root().add_submenu(
    L"My Mod Settings",
    L"Configure My Mod.");
```

API 1.3 can instead give the provider its own top-level tab:

```cpp
if (menu.supports(erui::Capability::custom_tabs)) {
    erui::TabOptions tab{};
    tab.tab_id = "settings";
    tab.title = L"My Mod Settings";
    tab.preferred_order = 100;

    erui::Page page = menu.add_tab(tab);
    if (page.valid()) {
        page.add_toggle(
            L"Enable My Feature",
            L"Turn this mod feature on or off.",
            1);
    }
}
```

The returned object is an ordinary `Page`: all existing row builders and
automatic pagination rules still apply. Leaving `tab.icon` empty selects the
host fallback glyph. Supplying artwork requires exactly 32x32 decoded RGBA8
pixels; follow the [Custom Configuration tabs guide](../guides/custom-tabs.md)
for the complete C++ example, icon conversion, localization and ordering
contract.

## Capability and fallback policy

Custom tabs are game-build-sensitive. A valid API 1.3 connection can omit
`Capability::custom_tabs` when the host could not validate the required native
interfaces for the installed executable. Check the capability before adding a
tab. A mod may then omit its optional UI or keep using an API 1.2-compatible
built-in page/submenu as a fallback.

Do not infer custom-tab availability merely from successful API negotiation,
a non-null function pointer, or the presence of an extra tab in another mod.

## Stable identity and lifetime

- Keep `provider_id` and provider-local `tab_id` stable and untranslated.
- Translate only the visible title and rows before registration.
- Register topology once from the normal startup worker. Tab descriptors and
  page topology are immutable after commit.
- Retain the successful `Registration` for supported row reads and writes.
- The host copies the tab ID, title and icon bytes synchronously during the
  builder call; callback code and callback state retain their ordinary
  process-lifetime requirements.

## Strict-C clients

A strict-C client that adopts API 1.3 must:

1. zero `ERUI_Api`, set `size` to `ERUI_API_V1_3_SIZE`, and request
   `ERUI_API_VERSION_1_3`;
2. verify the returned version and complete 376-byte table;
3. check `ERUI_CAP_CUSTOM_TABS` and the `add_tab` function pointer;
4. zero and size `ERUI_TabIconDesc` and `ERUI_TabDesc`, leaving reserved fields
   at zero; and
5. treat the returned `ERUI_PageHandle` like any other provider-owned page.

Do not enlarge an API 1.2 table while continuing to request API 1.2. Version
and size identify one frozen contract together.

## Validation checklist

- Test graceful connection failure against an API 1.2-only host.
- Test the capability-absent fallback path on a valid API 1.3 connection.
- Verify the stable diagnostic key is `provider_id/tab_id`.
- Test opaque and transparent icons, or the empty-icon fallback.
- Add enough rows to exercise automatic page slicing.
- Test L1/R1, held repeat, wrapping, mouse selection and close/reopen behavior.
- Test coexistence and deterministic order with another custom-tab provider.
- Confirm an existing binary built against API 1.2 still works with the new
  host without recompilation.
